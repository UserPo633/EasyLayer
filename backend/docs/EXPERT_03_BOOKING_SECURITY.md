# 전문가 3 — 예약 정확성·개인정보·복귀 설계

검토 기준: v0.3 실제 `bridge/core.py`, `bridge/source.py` 및 기존 회귀 테스트. 업데이트: v0.4, 2026-09-30 KST.

## 결론

EasyLayer의 경쟁력은 예약 문구 생성보다 **승인된 한 건을 중단 후에도 안전하게 이어가고, 결과가 불명확할 때 추가 예약을 만들지 않는 것**에 있다. 웹 시뮬레이터와 MCP가 같은 Engine과 데이터베이스를 사용해야 이 약속을 검증할 수 있다.

## 확인한 문제와 반영한 변경

| 기존 문제 | v0.4 반영 | 검증 방법 |
|---|---|---|
| 화면의 만료 상태만 계산하고 승인 연락처를 DB에 남김 | 만료를 실제 상태로 저장하고 연락처 필드를 비움 | 만료 후 승인 거부·재시작·저장값 확인 |
| 중단 후 본인 예약을 찾는 API 없음 | `resume(owner)`가 본인의 미확정 쓰기부터 복구 | 다른 소유자 격리, 재시작 후 unknown 우선 복구 |
| 복귀 시 기존 검토 링크 재사용 문제 | draft만 새 capability와 revision을 발급하며 이전 링크 무효화 | 오래된 링크 승인 거부, 기존 만료 시간 보존 |
| 승인했지만 제출 전인 초안을 철회할 수 없음 | draft/approved에 한해 `cancel(draft_id, owner)` 제공 | 취소 후 승인·제출 불가, 연락처 제거 |
| 같은 draft만 중복 제출을 방지 | 같은 사용자·서비스·담당자·날짜·시간의 pending/unknown/verified도 확인 | 서로 다른 두 draft를 동시에 완료해 원본 POST 1회 |
| 제출 중인 DB 행에 연락처가 남음 | pending 선점 시 연락처를 메모리로 옮기고 DB 필드를 비움 | 등록을 잠시 멈춘 상태에서 저장값 확인 |
| source factory 예외가 pending을 남길 수 있음 | 원본 생성 실패도 제출 전 오류로 처리 | 승인 상태 복구 후 정상 재시도 |

## API 계약

- `resume(owner)`는 한 건의 공개 상태를 반환한다. pending/unknown이 있으면 먼저 반환하고, 없으면 최신 draft/approved/verified를 반환한다. 없으면 `{state: 'none', draft_id: null}`이다.
- draft 복귀 시 `review_url`, 증가한 `revision`, 기존 `expires_at`을 반환한다. 기존 동의나 만료 시간을 연장하지 않는다. approved 상태에는 다시 검토 URL을 발급하지 않는다.
- `cancel`은 **미제출 초안 취소**다. 이미 원본에 생성된 예약 취소가 아니다. pending/unknown/verified를 취소로 표시하지 않는다.
- 중복 대상은 `state: 'duplicate'`, `related_draft_id`로 기존 본인 기록을 가리킨다. 연락처를 지우며 추가 POST를 보내지 않는다.
- `verified: true`는 원본 read-back 일치 후에만 반환한다. 등록 응답을 잃어 원본 hash가 없는 unknown은 성공으로 복구했다고 주장하지 않는다.
- 중복 검사와 pending 선점은 하나의 SQLite 쓰기 트랜잭션에 포함한다. 네트워크 요청은 그 잠금을 해제한 뒤 수행한다.

## 채택하지 않은 확장

- **모델의 “네”만으로 승인**: 현재 독립 검토 페이지의 구체적 조건과 연락처 확인이 필요하다.
- **unknown 자동 재등록**: 원본이 멱등성 키를 지원하는 것으로 검증되지 않아 중복 부작용을 유발할 수 있다.
- **완전한 예약 취소·변경**: 원본 취소 조건, 환불, 본인 확인까지 별도 검증해야 한다. 초안 취소만 구현했다.
- **OAuth 서버 직접 구현**: 이번 목표는 작동하는 MCP 기반 시뮬레이터다. 공개 서비스 인증·계정 연결은 별도의 배포 단계다.

## 검증 결과와 한계

기존 core 회귀 14건과 신규 lifecycle 회귀 12건을 통과했다. 신규 테스트는 합성 SourceFixture를 사용하며, 원본 서비스 통합 성공이나 실제 Alexa 실행 증거가 아니다. 원본 어댑터의 HTTP 계약 검증은 QA 전문가의 별도 테스트와 함께 판단한다.

연락처 정리는 현재 DB 행의 논리적 삭제다. 저장 장치의 암호학적 완전 삭제를 보장하지 않는다. 정리 시점은 Engine 시작 또는 다음 draft 작업이며, 프로세스가 꺼진 동안 자동으로 실행되는 보존기간 작업은 없다. 공개 배포에는 암호화, 정기 정리, 기록 보존 정책을 추가해야 한다.

중복 방지는 이 DB와 동일한 소유자·예약 대상 범위의 보수적 장치다. 다른 기기에서 원본 사이트에 직접 만든 예약, 다른 계정의 예약, DB 손실 후 재시도까지 보장하지 않는다. 원본에서 이미 취소한 예약의 같은 슬롯 재예약도 자동 허용하지 않는다. 검증된 원본 취소·조정 절차가 생기기 전에는 직접 원본 사이트에서 처리한다.

현재 local MCP 토큰은 단일 개발자 소유자로 매핑된다. 웹 세션 쿠키가 여러 개 있다고 여러 사용자 계정으로 격리되는 것은 아니다. 검토 링크는 소유자에게 전달하는 비밀 capability이며, 체크박스는 명시적 UI 승인을 나타낼 뿐 인간임을 암호학적으로 증명하지 않는다.
