# EasyLayer v0.2 업데이트 — 2026-09-21 KST

## 이번 버전의 목적

기존 예약 연결 코드를 다중 턴 대화와 같은 상태로 묶고, 실제 서버 검증을 재현할 수 있는 패키지로 정리했다. 실제 서버·AWS·브라우저에서 성공했다는 의미는 아니다.

## 구현한 변경

1. **예약 연결 토큰 오류 수정:** Easy!Appointments 1.6.0은 쿠키에 HttpOnly를 설정한다. 기존 adapter가 `document.cookie`만 읽던 것을 원본 페이지의 `vars.csrf_token`을 우선 사용하도록 변경했다. 원본 보안 설정은 바꾸지 않았다. 회귀 테스트가 페이지 토큰 경로를 검증한다.
2. **공통 예약 상태:** 서비스·담당자·날짜·시간대·가능 시간·연락처·확인 revision을 `booking-session.js`에서 관리한다. 음성/텍스트/버튼이 같은 상태에 작용한다.
3. **다중 턴 Bedrock planner:** 수업 선택 외에 날짜/시간대 변경, 표시된 시간의 순번 선택, 재질문, 요약 요청을 처리할 JSON 계약을 추가했다. 실제 Bedrock 호출은 실행하지 않았다.
4. **기본 명령 모드:** 정확한 수업 이름, `Tuesday morning`, `목요일 오전으로 바꿔줘`, `내일`, `두 번째로`, `다시 읽어줘`를 규칙으로 처리한다. 범위 밖 표현은 부분 실행하지 않고 거절한다. 기본 명령을 AI라고 표시하지 않는다.
5. **음성 안내:** 브라우저 음성 합성으로 안내와 예약 요약을 읽는다. 음성 인식은 편집 가능한 요청창에 기록하고 사용자가 전송한다. 완전한 hands-free 에이전트는 아니다.
6. **확정 전 검토:** 수업·담당자·날짜/시간·금액에 더해 전송할 연락처를 화면에 보여준다. 확인란 체크 후 확정 버튼 또는 정확한 `confirm booking` / `예약 확정` 요청으로 실행한다. LLM은 확정 권한이 없다.
7. **시간 경쟁 복구:** 등록 전 실제 availability를 다시 조회하고, 이미 마감됐으면 연락처를 유지하면서 대안을 표시한다. 새로운 시간은 새 확인이 필요하다.
8. **새로고침 보호:** POST 이전에 sessionStorage에 제출 중 상태를 기록한다. 새로고침 후에는 새 예약을 보내지 않고 기존 결과를 확인한다. 연락처는 저장하지 않는다. 탭을 닫거나 다른 탭을 사용하면 보호되지 않으며 서버 전체의 idempotency가 아니다.
9. **원본 조건 재검사:** 수업 이름·가격·기간, 담당자 이름·시간대·서비스 연결, 필수 연락처 필드 변경 시 이전 확인을 무효화한다. 지원하지 않는 필수 사용자 정의 필드/동의/인증은 원본으로 안내한다.
10. **화면 재구성:** 큰 선택 카드, 고정된 예약 요약, 요청 입력창, 한국어/영어, 글자 크기, 단계 표시를 추가했다. 시각·스크린리더 실기 검증은 별도다.

## 실제 검증 상태

현재의 정확한 결과는 `evidence/release-checks.json`과 `evidence/preflight.json`을 기준으로 본다.

- 기존 및 신규 순수 로직·계약 테스트 실행.
- jsdom으로 실제 UI 스크립트의 DOM 이벤트 흐름을 검사. 이는 브라우저 화면 렌더링·마이크·원본 서버 검증이 아니다.
- Python/JavaScript 구문 검사 실행.
- Docker, PHP, MariaDB 미설치. `apt-get update`는 실행 환경의 사용자/그룹 권한 제한으로 실패. 원본 실행은 못 했다.
- AWS region/model/인증 미설정. 실제 Converse 호출 없음.
- Cloud Browser는 로컬 `file:` URL 열기를 보안 정책으로 거절했다. 브라우저 화면·음성·접근성 실기 검증 없음. 다른 브라우저 경로로 우회하지 않았다.
- 실제 source 예약, 실제 source 충돌, native DB 기록, 브라우저 시각 QA는 미검증.

## 다음으로 실행할 순서

1. Docker Desktop이 있는 PC에서 ZIP을 풀고 프로젝트 폴더로 이동.
2. `python scripts/start_demo.py`
3. `http://localhost:8080/easylayer-demo/connected.html`에서 기본 명령 또는 버튼으로 실제 예약 확인.
4. `python scripts/check_source.py`로 원본 등록·기록 재조회·중복 시간 거절 검증.
5. `npm ci`, `npx playwright install chromium`, `npm run test:live`로 실제 UI 충돌 복구 확인.
6. AWS 설정 후 `python scripts/start_demo.py --ai` 실행. `scripts/benchmark_bedrock.py --run`으로 실제 호출 증거 확보.
7. 원본 예약과 Bedrock 모두 성공한 다음 영어 데모 영상 제작.

공개 저장소 생성·클라우드 배포·Devpost 참가 등록·제출·영상 게시를 수행하지 않았다.
