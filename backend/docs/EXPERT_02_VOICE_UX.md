# EasyLayer v0.4 — 음성·접근성 UX 전문가 검토

검토일: 2026-09-30 KST. 검토 대상: 실제 v0.3 코드와 이번 v0.4 구현. 사용자 인터뷰나 사용성 실험은 수행하지 않았다.

## 핵심 판단

웹 화면은 이 대회에서 유효한 실행 표면이다. 핵심은 기존 예약 시스템의 조회·초안·승인·접수·원본 확인이 하나의 MCP 상태를 공유하는지다. 화면을 Alexa+처럼 보이게 만드는 것만으로 연동을 입증할 수는 없다. 새로운 `bridge/simulator/`는 자체 시뮬레이터이며, native Alexa+ 실행 여부를 명시한다.

대상은 작은 폼이나 여러 단계의 예약 화면을 다루는 데 부담을 느끼는 성인이다. 고령자 전체에 대한 접근성 효과, 인지 능력, 완료 시간 단축을 검증 없이 주장하지 않는다. 하나의 소스-backed 예약을 끝까지 이해하고 이어갈 수 있는지가 이번 프로토타입의 평가 질문이다.

## 이번에 구현한 흐름

1. 연결된 예약 시스템에서 서비스·담당자를 조회한다. 담당자 시간대로 오늘 날짜와 예약 시간을 표시한다.
2. 실제 빈 시간을 선택하면 MCP `create_booking_draft`로 초안만 만든다.
3. 별도 검토 페이지에서 연락처와 예약 정보를 확인하고 승인한다. 연락처를 도구 인수나 음성 명령에 넣지 않는다.
4. 화면으로 돌아와 상태를 조회한다. `approved`는 ‘승인됨 · 아직 예약 전’으로 표시한다.
5. 명시적 완료 버튼으로 접수한다. 서버가 원본을 다시 확인한 `state=verified` 및 `verified=true` 결과에만 영수증을 표시한다.
6. 다시 방문하면 `resume_booking`으로 서버 소유권이 적용된 최근 초안을 복구한다. 로컬 저장소에 연락처, capability URL, bearer를 저장하지 않는다. 검토 링크가 회전하면 오래된 탭이 무효일 수 있음을 안내한다.

## 실패와 복귀 설계

| 상태 | 사용자 표현 | 허용 행동 |
|---|---|---|
| draft | Review needed · not booked | 별도 검토, 상태 조회, 미접수 초안 폐기 |
| approved | Approved · not booked yet | 명시적 접수, 조회, 미접수 초안 폐기 |
| pending / unknown | Checking / Outcome needs checking | 기존 접수 확인, 상태 조회. 새 초안·재접수 금지 |
| duplicate | An existing booking needs attention | 기존 예약 복귀 후 확인 |
| changed / conflict | Details changed / Time unavailable | 새 조건을 다시 선택하고 신규 승인 |
| expired | Draft expired | 신규 초안과 신규 승인 |
| verified | Booking verified | 확인된 접수 번호, 다음 별개 예약 시작 |
| cancelled | Unsubmitted draft discarded | 다시 선택. 원본 예약 취소라는 표현 금지 |

네트워크 오류가 접수·상태 조회 후 발생하면 기존 요약을 남기되 최신 상태 미확인으로 바꾼다. 이전 `approved` 화면의 완료 버튼이 살아 있는 채로 남지 않도록 차단한다. 원본 연결이 실패하면 실제 복구 행동을 안내하며 임의의 시간이나 샘플 서비스로 대체하지 않는다.

## 음성 기능의 경계

현재 웹 시뮬레이터는 생성형 대화가 아닌 guided flow다. 브라우저 음성 입력과 읽어주기는 선택 기능이다. 지원 명령은 `find times`, `earlier`, `later`, `resume booking`, `read summary`, `check status`이며, 인식 결과를 텍스트로 먼저 보여주고 사용자가 실행한다. earlier/later는 현재 조회한 실제 가용 시간 목록에서 인접한 시간으로 선택만 이동한다. 초안을 만들거나 승인·접수하지 않는다. 음성이나 자유 텍스트로 승인·예약 접수를 실행하지 않는다. 보이는 요약과 읽는 요약은 동일한 MCP 반환 데이터에서 만든다.

브라우저 음성 인식이 없거나 허용되지 않으면 버튼과 키보드로 전체 흐름을 수행할 수 있다. 마이크 버튼 근처에 브라우저 음성 서비스 사용을 안내한다. 실제 Alexa 호출, 생성형 의도 해석, 다른 기기 간 account-linked 복귀를 구현했다고 표현하지 않는다.

## 접근성 선택

- 기본 본문 18px, 서비스 요약 16px 이상, 대부분의 선택·행동 영역 최소 48px.
- 실제 label, fieldset, legend, heading, link, button과 키보드 focus ring 사용.
- 단계와 상태는 색상만으로 구분하지 않고 문구로 함께 표시.
- 날짜·시간·시간대를 함께 제공하고 임의의 사용자 위치로 변환하지 않음.
- 비동기 상태는 `role=status`, 오류는 `role=alert`, 전체 대기 상태는 `aria-busy`로 표시.
- 좁은 화면에서는 한 열로 배치하고 감소된 동작 환경설정을 존중.
- 개인 연락처·검토 URL·도구 인수를 최근 호출 기록에 남기지 않음.

위 항목은 구현 선택이며 WCAG 준수 인증이 아니다. 실제 스크린리더·터치·마이크·브라우저 레이아웃 검증은 별도 기록이 필요하다.

## 전문가 간 이견과 결정

- 심사 전략: 자유 자연어 시연이 강한 인상을 줄 수 있으나 현재 연결되지 않은 planner를 작동하는 척해서는 안 된다. 이번 데모는 선택형 화면과 실제 MCP 흐름을 우선한다.
- 아키텍처: Alexa runtime을 필수 선행조건으로 두지 않는다. 자체 simulator 허용 범위에서 계약과 상태를 입증한다.
- 보안: 브라우저 저장 초안 ID만으로 복귀를 설계하려던 안을 서버 `resume_booking`으로 변경했다. capability를 저장하지 않고 새 검토 링크로 복귀한다.
- 제품: 초안 폐기를 원본 예약 취소로 부르지 않는다. 불확실한 접수 상태에서 새 초안 만들기를 열어 두는 편의성은 중복 접수 위험 때문에 제외했다.

## 다음 사용자 검증

예약 경험에 부담을 느끼는 성인 3–5명에게 선택→중단→복귀→검토→접수 과제를 제시한다. ‘지금 예약이 되었는가?’, ‘다음 행동은 무엇인가?’, ‘가격과 시간대는 무엇인가?’를 각 상태에서 본인의 말로 설명하게 한다. 완료 시간이나 성공률 목표를 실제 결과로 혼동하지 않고, 실패 원인과 도움 요청을 기록한다. 특히 unknown 상태에서 다시 예약하려 하는지 관찰한다.
